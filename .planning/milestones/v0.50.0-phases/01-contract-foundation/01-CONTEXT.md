# Phase 1: Contract Foundation - Context

**Gathered:** 2026-09-02
**Status:** Ready for planning

<domain>
## Phase Boundary

This phase delivers a **documented, configurable degenerate-input contract** and proves it on **one reference component (MarketModel)**. It establishes the pattern — the configuration surface, the internal helpers, the roxygen contract doc, and the strict/lenient behavior — that Phases 2-3 will apply uniformly across all models, statistics, and pipeline stages.

In scope: the contract document, the mode-switch configuration surface, shared internal helpers in a new `R/contract.R`, and refactoring MarketModel to fully use them as the exemplar.

Out of scope: applying the contract to other models/statistics (Phase 2), pipeline/window/export and external-package hardening (Phase 3), and the regression net / R CMD check gate (Phase 4).

</domain>

<decisions>
## Implementation Decisions

### Contract Configuration Surface
- The strict/lenient mode switch lives on a **`ParameterSet` field** with a **package-option fallback** (`options(eventstudy.degenerate_handling = ...)`); a single internal resolver `.resolve_degenerate_mode()` reads the ParameterSet value first, then the option, then the default.
- **Default mode is `"lenient"`** — preserves the current warn-and-return-NA behavior and satisfies CONTRACT-05 (valid-input behavior unchanged).
- Mode values are named **`"lenient"` / `"strict"`**.
- Mode is threaded into components by reading from the ParameterSet and passing it into the model's `fit()` context; the package-option fallback and default are resolved centrally by `.resolve_degenerate_mode()` so no component reads the raw option directly.

### Contract Semantics
- In **strict mode**, degenerate input raises a descriptive error containing the **component name + offending `event_id` and/or `firm_symbol` + the reason** (e.g. "zero variance", "insufficient observations").
- In **lenient mode**, emit **exactly one warning per (event_id, firm_symbol) per fit call**; duplicate warnings for the same event are suppressed.
- NA propagation means: `is_fitted = FALSE` → abnormal returns return all NA → all downstream statistics are NA. The event is not dropped and zeros are not substituted.
- Degenerate conditions covered by the contract: **<2 finite estimation observations**, **zero/near-zero variance** (`sd < .Machine$double.eps`), **single-event group**, and **NA propagation**. Perfect collinearity is deferred to Phase 3 (PIPELINE-03).

### Reference Component & Artifacts
- **MarketModel** is the reference component (default model, simplest OLS, most-used).
- The contract is documented as a **roxygen topic in a new `R/contract.R`** (`@name degenerate-input-contract` or similar), findable via `?` in the installed package docs.
- Shared internal helpers live in **`R/contract.R`** (e.g. `.resolve_degenerate_mode()`, `.signal_degenerate()` / `.handle_degenerate()`) so Phases 2-3 reuse them.
- **MarketModel's existing scattered guards are refactored onto the new helper** so it becomes a full exemplar of the pattern, not a helper bolted alongside old code.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `ParameterSet` (`R/parameter_set.R`) — `lock_objects = FALSE`, so a new `degenerate_handling` field can be added cleanly; already validates its member objects.
- `ModelBase` (`R/models.R`) — has a read-only `is_fitted` active binding backed by `private$.is_fitted`; the contract's lenient path sets this to FALSE.
- `MarketModel` (`R/models.R:124`) — already contains partial guards: `ss_market < .Machine$double.eps` zero-variance check (line ~76), a `tryCatch` around `lm()` that sets `is_fitted` and warns on failure, and an "is not fitted. Returning NA abnormal returns." warning path. These are the guards to unify under the helper.
- Other models (`MarketAdjustedModel`, `ComparisonPeriodMeanAdjustedModel`, `LinearFactorModel`, GARCH) already emit ad-hoc "insufficient estimation data" warnings — Phase 2 targets, but they confirm the pattern the helper must generalize.

### Established Patterns
- Guard style: `if (sd < .Machine$double.eps)` and `tryCatch(..., error = ...)` returning NA + `warning()`.
- Error style: `stop("<context>: <what went wrong>", call. = FALSE)`.
- Internal helpers use leading-dot snake_case and `@noRd`.

### Integration Points
- New `degenerate_handling` field on `ParameterSet$initialize()` (default resolves via helper).
- `MarketModel$fit()` / `abnormal_returns()` call the shared helper instead of inline guards.
- New `R/contract.R` file for doc + helpers; NAMESPACE regenerated by roxygen2.

</code_context>

<specifics>
## Specific Ideas

- The single resolver `.resolve_degenerate_mode()` is the choke point: ParameterSet field → package option → default `"lenient"`.
- Warning de-duplication is keyed on `(event_id, firm_symbol)` per fit call.
- The reference-component acceptance test must show identical numerical output on a valid (non-degenerate) input before and after the contract change (CONTRACT-05).

</specifics>
